## 指标口径

| 指标 | 来源或计算方式 | 日期筛选 |
| --- | --- | --- |
| 机器人资产 | `balance.total_bot`；旧服务未提供时回退 `balance.total` | 不影响 |
| 账户累计盈亏 | `profit.profit_all_coin` / `profit_all_ratio` | 不影响 |
| 区间已实现收益 | 区间内已平仓交易 `close_profit_abs` 之和，兼容回退 `profit_abs` | 影响 |
| 累计收益曲线 | 将交易完整已实现盈亏归属 UTC 平仓日，从区间起点由零累计 | 影响 |
| 首页收益百分比 | 区间累计已实现收益 / `balance.starting_capital`；图表按百分数显示 | 影响分子，初始资金基准不变 |
| 每日收益 | 按 UTC 平仓日汇总完整已实现盈亏 | 影响 |
| 收益日历 | 按独立的完整 UTC 月份统计 | 使用日历自己的月份 |
| 持仓总收益 | 优先 `total_profit_abs` / `total_profit_ratio`，包含分批退出的已实现部分；旧服务回退 `profit_abs` / `profit_ratio` | 不影响 |
| 单笔已平仓收益 | `close_profit_abs` / `close_profit`，兼容回退 `profit_abs` / `profit_ratio` | 记录按平仓日期筛选 |
| 区间胜率 | 盈利笔数 / 区间全部已平仓笔数 | 影响 |
| 盈利因子 | 区间盈利总额 / 区间亏损总额的绝对值 | 影响 |
| 单笔期望 | 区间净收益 / 已平仓笔数 | 影响 |
| 平均盈利、平均亏损 | 分别对盈利交易、亏损交易求均值 | 影响 |
| 交易对表现 | 在区间内按交易对汇总平仓收益，按金额降序排列 | 影响 |
| 历史最大回撤、夏普比率 | `/profit` 返回的全历史指标 | 不影响，单独标注 |
| 金额单位 | 服务端 `stake_currency` | 不影响 |

盈亏保留正负号；USDT 不会被当作美元显示。收益以服务器返回值为准，客户端不从成交价重新估算手续费、资金费或杠杆损益。

### 收益百分比示例

服务器初始资金为 25,000 USDT，近 30 天已实现收益为 2,393.43 USDT，图中显示 `+9.57%`。拖动到某日时，使用该区间从起点累计到该日的收益除以同一个初始资金。

这个百分比不是单笔收益率之和，也不是相对区间期初净值、当前资产或扣除资金进出后的时间加权收益率。分母使用服务器当前提供的 `starting_capital`；若服务器调整这一数值，历史曲线的百分比也会随之变化。分母缺失、非正数或非有限值时不估算。

### 胜率示例

10 笔已平仓交易中有 6 笔盈利、3 笔亏损、1 笔持平，胜率为 `6 / 10 = 60%`。持平交易仍计入分母。

盈利总额为 120，亏损总额为 -60，则盈利因子为 `120 / 60 = 2`，单笔期望为 `(120 - 60) / 10 = 6`。

### 缺失值与空区间

- 没有交易时，胜率与单笔期望显示 `—`。
- 只有盈利、没有亏损时，盈利因子显示 `∞`；没有盈利也没有亏损时显示 `—`。
- 缺失数值不默认为零；区间内存在缺失或非有限盈亏时，不显示不完整的胜率、收益曲线或排名。
- 完整数据中的无交易日可以是零收益，和“缺失数据”不同。

## 日期与行情

所有日级统计使用 UTC；设备本地时区用于交易时间展示。

区间采用 `[开始日 00:00, 结束日次日 00:00)`，自定义范围包含起止日。以**平仓时间**决定归属，开仓在区间外但平仓在区间内的交易也会计入；尚未平仓的交易不计入已实现区间统计。

收益日历使用完整自然月。历史删除的截止日则不包含当天，二者边界不能混用。

K 线通过 `pair_candles` 请求最近最多 240 根，按服务端列名解析 OHLC。实际根数取决于服务端缓存，不能保证覆盖某笔历史交易的持有期间。

## API 路由

以下路由相对于规范化后的 `/api/v1` 根路径。

| 方法 | 路由 | 用途 |
| --- | --- | --- |
| POST | `token/login` | 用 API 用户名密码登录 |
| POST | `token/refresh` | 使用刷新令牌续期 |
| GET | `show_config` | 机器人配置与显示单位 |
| GET | `profit` | 账户盈亏与历史风险 |
| GET | `balance` | 机器人资产 |
| GET | `status` | 当前持仓 |
| GET | `performance` | 服务端交易对表现快照 |
| GET | `daily` | 服务端最近 90 天日收益快照 |
| GET | `trades` | 已平仓历史、完整分页 |
| GET | `pair_candles` | 指定交易对和周期的 K 线 |
| GET | `trade/{id}` | 删除前逐笔核对最新状态 |
| DELETE | `trades/{id}` | 确认后的单笔历史记录清理 |

界面的区间分析与月历由完整交易历史在本机生成，不直接拿 `daily` 的 90 天结果代表任意范围。客户端未实现 force entry、force exit、撤单、机器人启停或配置写入接口。

## 完整历史与错误处理

- 快照并行读取配置、账户、持仓等接口，并等待完整交易历史完成后才整体发布。
- 历史以 `limit=500`、`order_by_id=false` 分页；检查总数、偏移、唯一 ID、已平仓状态和平仓日期。
- 多页读取后再次检查最新记录与总数；分页期间数据改变或不完整时，完整读取最多重新尝试一次。
- 普通 GET 对 502 / 503 / 504 最多重试两次。认证遇到 401 时共享令牌刷新任务，避免并发续期。
- HTTP 重定向被拒绝，TLS 使用系统证书校验。持续失败向用户显示错误，常规刷新保留先前快照。

## 历史清理校验

删除前必须读取并成功解析 `trade_id`、`pair`、`open_timestamp`、`close_timestamp`、`is_open`、`has_open_orders`，以及各委托的 `is_open`。

只有身份和原平仓时间一致、已平仓、严格早于截止日且没有未结束委托，才会请求 DELETE。响应必须为 `result=success`，交易 ID 一致且 `cancel_order_count=0`，才能计入已确认删除数量。

超时、连接失败和网关错误后的 DELETE 不会自动重试。明确的 401 拒绝可以续期，但再次发送前必须重新读取并核对状态。任何错误停止余下批次。该流程是客户端逐笔保护，并不提供数据库事务、并发锁或服务器端回滚。

## 兼容性

接口已按 Freqtrade 官方源码核对，并对 Freqtrade 2026.4 服务做过读取验证；这不等于保证所有历史或未来版本兼容。

部分展示字段提供回退，但删除所需的安全字段缺失时会拒绝继续。遇到版本差异，可提交脱敏的字段结构与错误描述，参见 [参与开发](../CONTRIBUTING.md)。
